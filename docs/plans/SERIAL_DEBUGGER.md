# waytty 串口调试规划

状态：基础调试功能已接入开发版，硬件与跨平台验收进行中。日期：2026-09-13。用户已授权开始实施。当前实现、限制与验证证据见[串口使用与验收](../SERIAL.md)；下文保留完整设计目标，不能将所有规划项视为已完成。

## 1. 入口与工作流

连接中心增加 **串口 / Serial**，与 SSH、Telnet 并列；“新建连接”可选择串口，显示设备和串口参数表单。连接后进入独立的串口会话标签，复用工作区的标签、重命名、颜色和关闭交互。

串口页列出可用设备及已保存配置，提供刷新、连接和编辑。设备项展示名称、系统端口标识、可获得的 USB VID/PID、序列号和多端口设备的端口编号；区分“未插入”“被占用”“权限不足”“不支持”。第一次打开页面只列设备，用户连接时才打开端口。

会话顶部显示设备、当前参数和连接状态；中间是接收区；底部是发送区、发送格式及换行选项。配置采用侧面板，窄屏平板改为独立设置页；软键盘和外接键盘均可操作。

## 2. 功能范围

| 能力 | 规划行为 |
|---|---|
| 连接参数 | 常用及自定义波特率、数据位、校验位、停止位、流控；默认 115200 / 8N1 / 无流控。实际可选组合由驱动能力决定，拒绝不支持的组合并说明原因 |
| 接收 | 文本与 HEX 视图；增量 UTF-8 解码，保留原始字节；可选 ANSI 终端视图；收发方向、应用接收时间、字节计数 |
| 发送 | 文本和 HEX；严格校验 HEX；可选无换行、CR、LF、CRLF，默认无附加换行；本地回显默认关闭；快捷发送和历史记录 |
| 调试控制 | 清空显示、暂停显示、搜索、复制、保存配置；暂停显示仍继续接收并显示缓存状态 |
| 信号控制 | 按驱动能力提供 DTR、RTS、BREAK 和可读取的线路状态；显式操作，不附带自动复位序列 |
| 记录 | 原始二进制导出及带时间/方向的记录；有界内存缓存、日志轮转、丢弃计数；应用时间戳不宣称是线上的精确字节时序 |
| 连续调试 | 定时发送、文件分块发送、多个设备会话；显示进度和停止入口，发送队列有上限 |
| 异常恢复 | 热插拔、读写超时、部分写入、驱动错误、端口占用；拔出后停止发送并取消待发队列，重连不重放旧数据 |

原始字节是数据源，文本、HEX、ANSI 都是显示方式，切换显示不重新编码原数据。串口字节流没有统一报文边界；默认不把一次读取当作一帧协议包。无效 UTF-8、NUL 和控制字节仍可在 HEX 和原始日志中查看。

串口配置和用户命名存本地；本机端口路径、USB 权限和打开句柄不进入现有主机同步。以后如需同步，只同步可移植的参数模板，在目标设备重新选择端口。

## 3. 跨平台接入

采用 **共享 Dart 串口服务接口 + 平台驱动**，不通过 shell 调用外部串口工具。

| 平台 | 候选实现 | 实施验证重点 |
|---|---|---|
| macOS | 优先验证 `flutter_libserialport` / `libserialport` FFI；若接口或分发要求不适合，再用原生适配器 | 设备枚举、优先展示 `/dev/cu.*` 并处理重复项、热插拔、驱动、打包及签名后的读写 |
| Windows | 同一桌面串口适配接口和 FFI 候选 | COM 枚举、COM10 及以上、端口独占、USB 驱动、断线、架构与 DLL 打包 |
| Android 平板 | USB Host 驱动；先验证 `usb_serial`，能力不足时用薄 Kotlin 插件接 `usb-serial-for-android` | USB OTG/Host 能力、用户设备授权、多端口芯片、拔出与权限失效、休眠和前后台、外接键盘 |

`flutter_libserialport` 是底层串口库的 Flutter 构建封装，适合列为桌面验证候选；其平台标签不能证明任意 Android 平板上的 USB OTG 接入已经可用。[包文档](https://pub.dev/packages/flutter_libserialport)

Android 官方要求检查 USB Host 支持并在通信前取得设备访问权限，设备断开后不能沿用旧连接。串口是 waytty 的可选能力，规划将 USB Host feature 声明为非必需，在不支持的平板上保留其他功能。[Android USB Host](https://developer.android.com/develop/connectivity/usb/host)

`usb_serial` 提供 Flutter 的 Android USB 串口接口；`usb-serial-for-android` 提供不依赖 root 的 USB Host 串口驱动，列有 FTDI、CP210x、CH340 等芯片支持。这些是候选依赖的能力声明，尚未在 waytty 真机验证。[usb_serial](https://pub.dev/packages/usb_serial)、[Android 驱动](https://github.com/mik3y/usb-serial-for-android)

选型前检查完整依赖链的许可证与打包方式。不能只依据 Flutter 包的 MIT 标签判断底层依赖：Dart `libserialport` 仓库提供 LGPL v3 许可证文件。S0 核验锁定版本、底层库与应用分发方式后记录最终选择。[许可证原文](https://github.com/jpnurmi/libserialport.dart/blob/main/LICENSE)

## 4. 与现有工程的关系

现有 `AppSession` 已提供会话标签接口，`TerminalSession` 还带有终端及录制字段，可复用交互和显示组件。当前 `HostProtocol` 和 `Host` 围绕网络地址、端口、凭据组织，不能用伪 IP 或 SSH 端口字段存串口配置。

新增独立模型与服务，名称暂定：

- `SerialDeviceInfo`：平台设备标识、USB 元数据、端口编号和能力；路径仅是当前定位信息，不单独充当永久设备身份。
- `SerialProfile`：用户名称、设备匹配信息、串口参数、文本/HEX 和换行偏好；采用单独的版本化持久化仓库。
- `SerialSession implements AppSession`：连接状态、当前设备身份、每次打开生成的会话代次、收发统计、缓存；需要 ANSI 时持有独立终端视图模型。
- `SerialService` / `SerialPortHandle`：枚举、变化通知、打开、受支持的配置、字节流、受限写队列、信号控制、关闭；驱动阻塞读写放后台，平台通道批量传递字节。
- `SerialCapabilities`：实际支持的参数/信号/流控；UI 据此开放选项，不能默默忽略配置。

串口数据经过单一读取入口，再分发给显示、记录和未来 AI 上下文；避免两个消费者直接争抢同一端口。每个物理端口在应用内只允许一个打开句柄，多视图共享该会话。

先独立接入 `SessionProvider` 和工作区，再按实际重复代码提取公共传输接口；不为串口第一版改写整个 SSH/PTY 栈。检查所有“本地/远程”二分逻辑，串口不能误入 SFTP、SSH 命令广播或本地 shell 操作。

预计涉及：连接中心、新建连接入口、会话 Provider、串口页面与服务、新配置仓库、Android 平台插件、共享多语言资源和发布脚本。默认中文，用户设备名、日志、HEX 和系统端口标识保持原文。

## 5. 连接与发送语义

打开设备和设置线路本身可能影响硬件，驱动打开行为必须用实际设备验证，不承诺“打开绝不会使开发板复位”。用户可以保存期望的线路状态，适配器明确报告不支持的控制。

发送结果区分“提交给驱动的字节数”“部分提交/结果未知”和“协议确认”；驱动写成功不代表目标设备已经处理成功。部分写入只能在同一个有效会话中按已确认偏移推进，超时或断开后不自动重试结果未知的部分。退出、拔出和会话关闭停止定时任务、释放读取订阅与句柄。

重连重新核对设备信息。没有唯一序列号且存在多个相同设备时要求重新选择，不按旧 COM 号或路径盲连；新的打开会话不会继承旧的待发送队列。

接收的控制序列和设备输出只是数据。ANSI 解析器自动应答、剪贴板访问、链接打开与其他副作用需要独立控制；纯查看和 AI 日志分析不应触发串口发送。

## 6. 与 AI 助手的衔接

串口调试本身不依赖 Pi 或模型 API，可先于 AI 助手交付。后续接入 [AI 运维助手规划](AI_OPERATIONS_ASSISTANT.md) 中的 `OpsToolBroker`：

- **分析记录**：用户选定当前会话的一段记录，携带参数和必要设备信息交给 AI，解释启动日志、乱码或协议字节；限制长度并处理敏感内容。
- **协助发送**：展示文本及实际编码后的 HEX、长度、换行和目标设备；授权绑定任务、设备身份、会话代次和准确字节。修改参数或重连后旧授权失效。
- **线路操作**：DTR/RTS/BREAK 独立列为会影响设备的工具，不混入只读分析；AI 不自动打开其他端口。

模型、Pi 或外部 MCP 客户端均走同一串口执行层。Android 可直接访问接在平板上的 USB 串口；如果使用 Agent 网关，工具仍在持有设备的客户端执行，客户端离线时不能继续操控该端口。

## 7. 实施顺序与验收

| 阶段 | 交付 | 验收条件 |
|---|---|---|
| S0 驱动验证 | 桌面与 Android 最小适配验证、能力和依赖记录 | 明确真实可用的配置组合、打包要求及候选库选择；模拟测试不能代替硬件结论 |
| S1 桌面可用入口 | 串口页、配置、独立标签、文本/HEX 基本收发、断线状态、中英文 | macOS 完成设备连接和回环收发；Windows 在目标系统单独构建和验证后标记支持 |
| S2 完整调试工作流 | 日志、搜索、快捷/定时/文件发送、线路控制和多会话 | 发送可中止、队列有界、拔出无重放、原始日志与实际字节一致 |
| S3 平板接入 | USB 授权、触控布局、键盘和生命周期适配 | 支持 USB Host 的实际平板完成授权/拒绝/拔出/重插、收发和后台恢复验证 |
| S4 AI 联动 | 选中记录分析、受控发送和信号工具 | 只读分析无 TX；拒绝无发送；变更目标/字节/会话后旧授权不可复用 |

关键回归包含跨读取分片的中文、非法 UTF-8、NUL 与全字节 HEX 往返；参数不支持、端口占用、部分写入和断开；高吞吐时界面响应、缓存上限和日志轮转；暂停显示仍接收；不同设备不串数据。

自动化使用可控假驱动和适用平台的虚拟串口/PTY；硬件验收覆盖现有可获得的 USB 串口适配器和回环夹具，逐个记录芯片、系统、驱动和验证过的参数。当前未打开任何用户串口、未发送字节，也未安装候选依赖。

首期处理普通串口字节调试；固件烧录、专用工业协议和 Bluetooth 串口按后续需要单独规划。
